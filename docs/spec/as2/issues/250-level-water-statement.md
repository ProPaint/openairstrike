# 250: the level file's two water statements

Status: decided (C5). Raised by C5. Affects `engine/include/as3d/defs.h` (`LevelDef`),
`engine/src/game/defs.cpp`, `tools/ref/defs.py`, the goldens `testdata/golden/as2/` and
`testdata/golden/gulf/defs_summary.json`.

## Facts

- The first game writes `water "<texture>" <level> <opacity>` (levels-txt.md); AirStrike 2 and
  Gulf Thunder write `water "<base>" "<shine>" <level> <opacity>`
  (as2/render-pipeline.delta.md 12.5, VERIFIED-DATA: 18 `as2` levels, every `gulf` level with
  water). The two forms never occur in the same file.
- levels-txt.delta.md says "`water` same syntax"; that is wrong for the argument list (the
  render delta's corrections table already says so for hmap.md).

## Choices

1. The form is told by the **statement's shape**, not by the game: a second argument that is
   quoted or not a number is the shine texture, and the level and opacity follow it. Any game
   reads either form, so the loader needs no game switch and the reference tools
   (`tools/ref/defs.py`) need none either.
2. `LevelDef::waterShine` holds the shine texture; empty for the first game's form.
3. Canonical serialization (levels-txt.md "Canonical serialization"): a line
   `waterShine=<name>` is written right after `waterAlpha` **only when the shine texture is
   present**. The first game's hashes are therefore unchanged; the `as2` and `gulf` level
   hashes changed (regenerated by deleting `defs_summary.json` and running
   `tools/ref/test_defs.py --game <key>`). levels-txt.md should list the optional field
   (correction for the orchestrator: C5 may not edit the base spec).
4. The shine texture is checked like the base texture in the reference validation (both exist
   in every shipped game: no new unresolved reference).

## Not changed

`tools/ref/hmap.py` has its own reduced level-list reader (`load_level_list`, used for its
vertex colours and preview only, not for any golden) that still reads the first form only;
it is outside this package.
